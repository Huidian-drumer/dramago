Execution pipeline

Creative Brief
  → Operation Router
  → Writer
  → Output Contract
  → Programmatic Merge / Append
  → Semantic Validator
  → Candidate Version
  → Compare-and-swap Adopt

CREATE 可以在 Writer 前选择轻量 ContentPlan 与 Mechanism Retrieval；EXPAND、REWRITE 和 CONTINUE 保持直接链路。

Selection and merge

selection_range 是程序输入，不只是 Prompt 文本。目标片段以字符区间解析和替换，范围外内容由程序保留。Provider 若返回错误类型或异常尺寸，候选不会进入可自动采用状态。

Version safety

任务基于明确 source_version_id。生成完成前重新读取作品当前版本；如果来源已过期，候选可保留，但 source_is_current=false。采用时执行条件更新：

UPDATE works
SET current_version_id = ?
WHERE id = ?
  AND current_version_id = ?

受影响行数不是 1 时返回 SOURCE_VERSION_CONFLICT，候选不会被删除。

Validation binding

candidate 保存 content_hash、validator_version 和 validated_at。checks 同时绑定 candidate id 与 content hash；采用前 hash 不一致会返回 VALIDATION_STALE。

Trace and privacy

Creative Trace 记录 task、operation、source/candidate、scope、provider/model、prompt template、merge、validation 与 adopt 状态。API Key、Authorization 和完整 Secret 不进入 trace。

Runtime boundary

当前演示链路仍使用同步长 HTTP WRITE。历史延迟实验说明旧约 90 秒边界来自 45 秒 × 2 的应用尝试，而不是已证明的固定宿主硬限制。Queue 与 durable execution 被记录为未来路线图，不在 v0.5.0 实施。
